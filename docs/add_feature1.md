# add_feature.md — Clipper: Tool Bootstrap (Install Recipe + Shim)

## Goal
Enable **one-command** environment carry-over of CLI tools across machines by:
- Recording each tool’s **install recipe** (e.g., `apt …`, `brew …`, `curl … | sh`, `cargo …`, `npm …`, etc.)
- Guaranteeing the **same command name** in the new environment via a **shim** generated by `clipper`
- Optionally recording a “real executable” (exec) if the user wants direct execution instead of shim delegation
- Supporting export/import as part of Clipper’s existing JSON flow

This feature is **not** a package manager. It is a **command handover / bootstrap** mechanism.

---

## Core Idea (Design Choice)
### Primary mode: *Name-first + Shim*
The user chooses the stable command name (`name`). Clipper guarantees that `name` exists by generating a shim in a known bin directory (user-level). The shim delegates to `clipper run <name>` (or an internal exec runner). This avoids unreliable auto-detection of real binary names across heterogeneous installers.

### Secondary mode: *Optional exec mapping*
If the user wants, they can set `exec`:
- `exec = "rg"` or `exec = "/usr/bin/rg"` or `exec = ["python","-m","http.server"]`
- Clipper can run this directly, but the shim approach remains the stable interface.

### Assisted detection (optional, best-effort)
After running install, Clipper can offer “candidate executables” by diffing known bin paths or manager-specific listing, then ask the user to select.

---

## User Stories
1. **Add a tool recipe**
   - I define a stable command name and how to install it.
   - Clipper stores it and can generate a shim.
2. **Bootstrap a new machine**
   - I import my clipper export file.
   - I run `clipper bootstrap` to create shims.
   - I run `clipper tool install --all` to install tools.
   - I can run the same commands as before (via shim).
3. **Run installed tools**
   - I type the tool command (shim) → clipper resolves and runs.
   - If `exec` is missing, clipper can try to run `name` directly or prompt to set `exec` (configurable).

## Proposed CLI (New Commands)
### 1) Add tool
```
clipper tool add <name> --install "<install_cmd>" [--exec "<exec_cmd>"] [--shell <sh>] [--tags <csv>]
```
Examples:
- Apt:
  - `clipper tool add rg --install "sudo apt-get update && sudo apt-get install -y ripgrep" --exec "rg"`
- Brew:
  - `clipper tool add fd --install "brew install fd" --exec "fd"`
- Curl script (prefer fixed destination):
  - `clipper tool add uv --install "curl -LsSf https://astral.sh/uv/install.sh | sh" --exec "uv"`
- No exec (shim-only):
  - `clipper tool add mytool --install "curl -fsSL ... | sh"`

### 2) Install a tool (run the stored recipe)
```
clipper tool install <name> [--dry-run] [--yes]
clipper tool install --all [--dry-run] [--yes]
```
Behavior:
- Executes `install_cmd` through a shell (default OS-appropriate).
- Records `installed_at` timestamp and last status in config (optional).
- If `exec` is not set, optionally run detection (see below) unless `--yes` disables prompts.

### 3) Bootstrap (create/update shims)
```
clipper bootstrap [--force] [--print-path]
```
- Creates/updates shims for all tool entries.
- `--force`: overwrite existing shims
- `--print-path`: outputs the shim directory and instructions to add to PATH

### 4) List / Remove / Edit
```
clipper tool list
clipper tool remove <name>
clipper tool edit <name> [--install "<cmd>"] [--exec "<cmd>"]
```

### 5) Run resolution (existing `clipper run`)
- If the query matches a tool entry with shim name, run that tool:
  - If `exec` exists: run `exec`
  - Else: try to run `<name>` on PATH (may hit shim again; avoid recursion via env flag)
  - If still unresolved: show a helpful error suggesting `clipper tool edit <name> --exec ...`

## Execution Model
### Shim → clipper
Shim calls clipper with a special command:
- `clipper __shim__ <tool_name> -- "$@"`
or:
- `clipper tool exec <tool_name> -- "$@"`

Clipper then:
1. Loads config → finds tool record
2. Determines target:
   - If `exec` is set: run it with forwarded args
   - Else: run resolved binary name = `<tool_name>` but **guard recursion** (env var)
3. Inherit stdin/stdout/stderr
4. Return the underlying exit code

### Recursion guard
Set env var when shim calls clipper, e.g.:
- `CLIPPER_SHIM=1`
When clipper tries to run `<tool_name>` directly, if `CLIPPER_SHIM=1` and it would re-invoke the shim, detect and error with guidance.

## Cross-Platform Shim Generation
### Shim install directory
Choose a user-writable, conventional bin path:

- Linux/macOS: `~/.local/bin`
- Windows: `%LOCALAPPDATA%\clipper\bin` (or `%APPDATA%\clipper\bin`)

Store this path in config for portability.

### Shim contents
#### Linux/macOS shim (POSIX shell)
File: `<shim_dir>/<name>` (chmod +x)
```sh
#!/usr/bin/env sh
exec clipper __shim__ "<name>" -- "$@"
```

#### Windows shim (cmd or PowerShell)
Prefer `.cmd` for compatibility:
File: `<shim_dir>\<name>.cmd`
```bat
@echo off
clipper __shim__ "<name>" -- %*
```

Optionally provide PowerShell `.ps1` too, but `.cmd` is usually enough.

### PATH guidance
`clipper bootstrap --print-path` prints instructions:
- POSIX: `export PATH="$HOME/.local/bin:$PATH"` (and suggest placing in shell rc)
- Windows: add `%LOCALAPPDATA%\clipper\bin` to user PATH

## Data Model (Config JSON)
Extend existing config (example structure; adapt to current schema):

```json
{
  "schemaVersion": 2,
  "commands": { /* existing */ },
  "tools": {
    "rg": {
      "name": "rg",
      "install": {
        "cmd": "sudo apt-get update && sudo apt-get install -y ripgrep",
        "shell": "sh"
      },
      "exec": {
        "type": "string",
        "value": "rg"
      },
      "tags": ["search"],
      "createdAt": "2026-01-13T00:00:00Z",
      "updatedAt": "2026-01-13T00:00:00Z",
      "lastInstall": {
        "status": "success",
        "installedAt": "2026-01-13T00:00:00Z",
        "exitCode": 0
      }
    }
  },
  "shim": {
    "dir": "/home/user/.local/bin"
  }
}
```

### Notes
- `tools` is keyed by `<name>` for O(1) lookup.
- `exec` can be one of:
  - string: `"rg"` or `"/usr/bin/rg"`
  - argv array: `["python","-m","http.server"]`
- Keep timestamps optional if you want minimalism.

## Optional: Assisted `exec` Detection (Best-Effort)
When `exec` is missing after install, optionally propose candidates:
1. **Manager-specific listing** (higher precision):
   - apt/dpkg: infer package name is hard; unless user provides it, skip.
   - brew: similarly needs formula name.
   - cargo: diff `~/.cargo/bin`
   - npm -g: use `npm bin -g` directory diff
2. **Directory diff** (works for many):
   - Snapshot executables in:
     - `~/.local/bin`, `/usr/local/bin`, `~/.cargo/bin`, `~/.npm-global/bin`, etc.
   - After install, diff and list new executables.
3. Prompt user via fuzzy selector:
   - “Select the executable for tool `<name>`”
   - Save chosen exec.

**Important**: detection must be optional and never blocks `bootstrap`/shim flow.

## Export / Import Changes
- Existing `clipper export` / `clipper import` should include `tools` and `shim.dir`.
- Maintain backwards compatibility:
  - `schemaVersion` bump to 2
  - On import of v1, initialize `tools` empty.

Merge behavior:
- `--overwrite`: overwrite tool entries by name
- `--merge`: interactive rename/skip/overwrite

## Implementation Plan (Codex Tasks)
### Task 1 — Data structures + persistence
- Add `tools` and `shim` fields to config model
- Implement load/save with schema migration v1 → v2

### Task 2 — CLI plumbing
- Add subcommands:
  - `tool add|list|remove|edit|install`
  - `bootstrap`
  - `__shim__` internal command (hidden from help)

### Task 3 — Shim generation
- Determine shim dir per OS (default + override via config/env)
- Generate shims for all tool names
- Ensure executable bit on POSIX
- Ensure `.cmd` on Windows
- Handle collisions:
  - If a file exists and not recognized as a clipper shim:
    - refuse unless `--force`

### Task 4 — Tool install execution
- Execute install command through shell:
  - POSIX: `sh -lc "<cmd>"`
  - Windows: `cmd /C "<cmd>"` (or PowerShell if chosen)
- `--dry-run`: print command only
- `--yes`: no prompts

### Task 5 — Shim runtime execution
- Implement `clipper __shim__ <name> -- args...`
- Resolve tool record:
  - If `exec` string → run it + args (split safely)
  - If `exec` argv → run argv + args
  - Else → run `<name>` + args with recursion guard
- Forward IO and exit code

### Task 6 — Tests
- Unit tests for:
  - config migration v1 → v2
  - shim file content generation per OS
  - command parsing and exec resolution
- Integration (where possible):
  - simulate `__shim__` path and ensure it invokes correct runner

### Task 7 — Docs
- Update README:
  - new commands
  - PATH setup
  - examples for apt/brew/cargo/npm/curl

## Design Constraints / Non-Goals
- Do not attempt perfect package manager parity.
- Do not attempt full “installed package inventory” scanning.
- Detection is best-effort; shim-based stability is the primary contract.

---

## Acceptance Criteria
- After import on a new machine:
  1. `clipper bootstrap` creates shims for all tools
  2. Running `<toolname>` invokes clipper (even before install)
  3. `clipper tool install --all` executes recorded recipes
  4. After install, `<toolname> --help` works (via exec or direct binary), or yields a clear actionable error suggesting `--exec`
